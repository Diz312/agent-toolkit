## Proposed

- **[fastapi](https://github.com/fastapi/fastapi/tree/b0a616d9fa301a50bf5809c64f97e5f2d6ae941d/fastapi/.agents/skills/fastapi)** (skill, agentic-app-dev, score 80): Official, from the FastAPI maintainers (105k stars, MIT). Current idioms: `Annotated` dependencies, return-type response models, SSE and JSON Lines streaming, `max_body_size`, native OpenTelemetry, `fastapi dev`/`run` with the entrypoint in `pyproject.toml`, uv and Ruff. Pinned to the last commit on the skill path, which is the content shipped in release 0.165.0 (2026-11-18). Instruction-only (SKILL.md plus 8 short references). skillshare audit: 10 LOW (external doc links). Two small mismatches with your rules: it suggests `ty` "if available" for types (your mypy rule still wins), and it suggests FastAPI Cloud only when no deploy target is chosen.
- **[single-agent-loop](https://github.com/anthropics/single-agent-loop-kit/tree/c43796287b83bec847db923f07131d1cc8de750d/skill)** (skill, agentic-app-dev, score 68): Official Anthropic (Apache-2.0, 610 stars), companion to the "when to fold subagents into your main agent loop" article. Audits a router-plus-subagents app, baselines it on an eval, then merges, folds or keeps each subagent as a tool, one measured change at a time, and stops for your decision at fixed check-ins (including before any paid eval run). The four helper scripts are stdlib-only Python (json, statistics, argparse); no network or subprocess calls. skillshare audit: 1 INFO. The repo is a reference kit marked "not maintained", so expect no upstream updates. Complements multi-agent-patterns (pending in #8), which covers design rather than migration.
